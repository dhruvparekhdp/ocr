# Handoff OCR-004 — Batch JSONL and long-scan OCR

## Summary

`jarvis/OCR-004` was created from `main`. OCR-005 was already pushed. This branch does not include the OCR-001 CI workflow, the OCR-002 service, or the OCR-005 GST checks.

`node batch.js <folder> --out results.jsonl [--workers N] [--no-resume]` writes one JSON object per PDF. A later run skips a file when the latest line for its sha256 has `status: "ok"`, including when the file was renamed. A failure is not done, so those bytes are tried again and a new line is appended. A half-written last line is ignored. `--workers` extracts several PDFs at once. Tesseract stays serialized in `ocr.js`. The summary on stderr has `total`, `processed`, `skipped`, `ok`, `failed`, `failures`, and `lowConfidence`.

A field scores 0.9 when its value sits on a schema label line, and 0.45 when it is a fallback (first date, or largest amount). OCR multiplies that by 0.8. Below 0.6 is low. The stored field value is not changed.

pdf-parse appends `-- n of N --` per page. Seven of those banners are 28 alphanumeric characters, which used to clear the floor of 25, so a 7-page scan was treated as text and never OCR'd. `substantiveAlnum` ignores those banners before the comparison. The fixture is `fixtures/sevenPageScan.js`.

## Assumptions

- Resume skips only `status: "ok"`. Errors are retried. The latest JSONL line for a hash wins.
- Same bytes in the same run are processed once. The second path is skipped.
- `--workers` defaults to 4 and is an in-process pool. It does not spawn extra Tesseract processes.
- The summary goes to stderr so the JSONL file stays one document per line.
- Low confidence is the label-vs-fallback score above, not a model probability. `batches.json` from `node index.js` is unchanged and still has no confidence.
- The 7-page fixture is generated in the test, not committed as a binary.

## Known gaps

- A mixed PDF (some text pages, some scans) is still one decision for the whole file.
- OCR of many pages is still one page after another on one Tesseract worker.
- The confidence score does not use Tesseract word confidence. A labeled value on an OCR page can stay at 0.72 and not be listed.
- A truncated JSONL line is skipped. The file it belonged to is retried, which is safe, but the bad line stays in the file.

## Security impact

No network calls, credentials, or upload storage. The JSONL contains extracted field text and a sha256 of the PDF bytes. Error lines keep a single-line message, cut at 300 characters.
