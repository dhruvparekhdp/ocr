# Handoff OCR-002 — OCR extract service

## Summary

`jarvis/OCR-002` was created from `main`. OCR-001 was already pushed on `jarvis/OCR-001` and is not contained in this branch. `fixtures/manifest.json` and `fixtures/generate.js` were copied from that branch so the service tests hit the same synthetic invoices, receipts, purchase orders, and transaction lists. `main` did not have those files yet.

`node service.js` (`npm run service`) listens on `127.0.0.1:8080` unless `OCR_SERVICE_HOST` / `OCR_SERVICE_PORT` are set.

- `GET /v1/health` → `{ "status": "ok" }`. No token. No document data.
- `POST /v1/extract` multipart field `file`, optional field `doc_type`. Header `Authorization: Bearer <OCR_SERVICE_TOKEN>`.
- Response: `doc_type`, `doc_type_confidence`, `pages: [{ page, text }]`, `fields: [{ name, value, confidence, page, bbox, method }]`, `warnings`.
- Types: PDF, PNG, JPEG, TIFF. Magic bytes and the filename extension must agree. Default limits: 20 MB, 20 pages.
- Uploads stay in memory. Disk writes happen only when `OCR_SERVICE_DEBUG_STORE=1`.
- Extraction is the existing schema heuristics. No LLM. `method` is the extractor name (`labeledId`, `company`, `address`, `date`, `amount`), never `"llm"`.
- PDF boxes are top-left PDF points. Image boxes are top-left source pixels. TIFF skips canvas preprocessing because `loadImage` segfaulted on a valid TIFF during this work; Tesseract reads the TIFF bytes.

If `OCR_SERVICE_TOKEN` is unset, `/v1/extract` returns 503. A known `doc_type` hint (any schema type except Unknown) selects that type and sets `doc_type_confidence` to 1.

## Assumptions

- Branch `jarvis/OCR-002` from `main` was allowed. Fixtures were taken from `jarvis/OCR-001` because `main` does not have them yet. Merging both branches will touch the same two fixture files; their contents match that branch at the time of the copy.
- Health is unauthenticated on purpose. `/v1/extract` is not.
- `doc_type` hint must match a schema type other than `Unknown`. Matching is case-insensitive; the response uses the schema's canonical name.
- Applicable fields only. A purchase order does not include `amount` or `documentNumber` in `fields`, because the schema says those extractors do not apply. A null applicable field would be returned with `confidence: 0`, `page: null`, `bbox: null`, and warning `field_not_found:<name>`.
- Confidence is deterministic and not a calibrated probability. Labeled matches use 0.9 (company-with-suffix 0.85, address 0.7, fallback 0.55), then the minimum of that and the mean OCR token confidence when a box is found.
- Default limits: 20 MB, 20 pages. Override with `OCR_SERVICE_MAX_BYTES` and `OCR_SERVICE_MAX_PAGES`.
- The bulk UI (`npm run web`) is unchanged and still has no auth.
- No LLM was added. There is no switch to turn one on.

## Known gaps

- CLI `batches.json` still has values only, no confidence or boxes.
- TIFF is not preprocessed (no upscale, denoise, or Otsu). A TIFF canvas cannot decode will still be OCR'd, or fail as `extract_failed` without a stack in the response.
- Boxes are missing (`bbox_not_found:<name>`) when the normalized value cannot be aligned to text items or OCR words. The fixture tests require a box for every non-null fixture field, and those passed.
- Mixed PDFs are handled per page here (sparse pages are OCR'd). The CLI path is still whole-document.
- No dependency audit or Actions run on this branch.

## Security impact

Bearer token required for extract. Comparison is SHA-256 then `timingSafeEqual`. The token is read from `OCR_SERVICE_TOKEN` and is not written into the repo. `.env.example` has empty values. Bind address defaults to loopback. Uploads are not stored unless debug store is explicitly `1`. Debug files use a random name and mode `0600`, not the client filename. Error bodies use a fixed message, not stack traces. No broker, network OCR, or LLM call was added.
