# Handoff OCR-001 — Dev setup, CI, and synthetic fixtures

## Summary

`jarvis/OCR-001` was created from `main` (the environment allowed a new branch). AUD-4 was already committed and pushed on `jarvis/AUD-4` before this branch existed.

`npm run setup`, `npm run lint`, `npm run typecheck`, and `npm test` are the one-command entry points (`make setup`, `make lint`, `make typecheck`, `make test`, and `make check` call the same scripts). `npm test` generates synthetic invoices, receipts, purchase orders, and bank-style transaction lists from `fixtures/manifest.json` and asserts document type, field values, row text, and batching. Each type is rendered twice: a text-layer PDF, and a Liberation Sans PNG wrapped in an image-only PDF. No customer documents were added.

GitHub Actions (`.github/workflows/ci.yml`) runs on push and pull request. It installs `tesseract-ocr`, `poppler-utils`, `fonts-liberation`, and `python3-venv`, then runs gitleaks 8.30.1, pip-audit 2.10.1, lint, typecheck, and test. CI is green on the implementation commit.

## Assumptions

- This repo is the ticket's `ocr` repo. The package name remains `document-classifier`.
- Branch name is `jarvis/OCR-001`, as the ticket asked.
- System `tesseract` and `pdftotext` are installed in CI and checked for presence. Document recognition stays on vendored tesseract.js. See `docs/DECISIONS.md`.
- `requirements.txt` stays free of packages because the app has no Python dependencies. pip-audit needs `python3-venv` because it builds a temporary virtualenv.
- `.env.example` lists the only `process.env` reads (`PORT`, `SCHEMA_PATH`). The process does not load dotenv. No dotenv dependency was added.
- ESLint and TypeScript are new devDependencies. Versions resolved by npm and locked: `eslint` ^10.14.0, `@eslint/js` ^10.0.1, `globals` ^17.14.0, `typescript` ^7.0.2, `@types/node` ^26.6.6. No production dependency was upgraded.
- `strict: false` is intentional so `checkJs` covers the existing JavaScript without a rewrite.
- Scan fixtures use Liberation Sans at `/usr/share/fonts/truetype/liberation/LiberationSans-Regular.ttf` (or the `liberation2` path). `npm run setup` installs `fonts-liberation` on apt-based systems.
- `npm run generate-samples` is unchanged and is not the CI test.
- No real customer documents. Fixture text is invented (including a fictional bank name, Harbor Bank Ltd).

## Known gaps

- The smoke-style `generate-samples.js` script is still present and still does not assert anything. CI does not call it.
- OCR assertions depend on Liberation Sans rasterization plus tesseract.js. They passed locally and on the Ubuntu 26.04 runner. A machine without that font fails the test until `npm run setup` (or the same apt packages) is run.
- System Tesseract is not wired into `ocr.js`. The presence check does not compare its output to tesseract.js.
- `pip-audit` has nothing to audit until a Python package is added to `requirements.txt`.
- `npm audit` still reports existing Node advisories. They were not upgraded in this ticket.
- Batch members in the product report still omit extracted fields. The fixture test asserts fields on `processDirectory` results, then checks batch membership separately.

## Security impact

No trading, broker, or network-OCR path was added. No secrets were written. `.env` is gitignored. `.env.example` has empty values, and a test fails if a value is filled in. gitleaks scans full git history in CI (`fetch-depth: 0`) and found nothing on `764bca8`. pip-audit found nothing because there are no Python requirements.

The upload server is unchanged: it still has no authentication. This ticket does not expose it.
